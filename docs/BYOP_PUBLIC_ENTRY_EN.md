# Bring Your Own Problem

This project is not only a theory and not only a software demo. It is an open path from a real competition/cooperation problem to an explicit model, a reproducible run, a bounded interpretation, and a reusable improvement request.

## Shortest path

**Understand -> Bring a Problem -> Model -> Run -> Interpret -> Challenge -> Extend**

1. Read the public idea guide.
2. Check the current capability ledger before modeling.
3. Fill the BYOP Problem Card: purpose, actors, candidates, third parties, hard constraints, unknowns, and what evidence would change your view.
4. Map only supported parts into baseline / candidate / actor / dimension / unit / constraint / UNKNOWN.
5. Run the current evaluator and interpret the output only within its declared boundary.
6. Return gaps, counterexamples, missing actors, missing constraints, interpretation risks, domain extensions, or core defects.
7. Extend at the smallest adequate layer: documentation -> teaching/template -> domain extension -> core/schema.

If the most important mechanism cannot be represented without distortion, the correct result is not to force a verdict. Record a **REPRESENTATION GAP**. That is valid open-source iteration input.

> Precise computation can enforce a rule. It cannot confer legitimacy on the rule.

Actors define their purposes. Institutions determine real-world authorization. The tool makes declared changes, constraints, and unknowns more visible.
