# 项目总览

## 一句话说明

**我们希望把“人们怎样在现实利益差异中竞争、合作并形成更大协作”这件事，从只能靠立场、经验和口号判断的问题，逐步变成能够把条件说清楚、把代价看见、把方案拿来比较、把错误找出来并继续改进的问题。**

这也是本项目参与者共同面对的任务：不是证明某一种合作方案永远正确，而是共同寻找、检验和改进那些能够让更多主体在现实条件下更好地实现自身利益，同时减少不必要伤害、支配、冲突升级和第三方成本转嫁的互动机制。

## 共同目的

人类社会中的个人、企业、组织、国家和各种共同体，都有自己的利益、能力、约束、信息和风险。竞争不会消失，利己诉求也不能靠道德要求取消。但互动规则不同，同样的主体可能走向完全不同的结果：

- 有的竞争促进效率和创新；
- 有的竞争不断升级，最后让所有相关方付出更大代价；
- 有的合作只是把成本转嫁给弱者或第三方；
- 有的合作则能让参与者在不要求彼此先变得无私的情况下，找到更可持续的共同收益；
- 有的联盟、阵营或共同体能够扩大协作能力，也可能制造新的排斥、依赖和系统风险。

本项目的共同目的，是**把这些差异背后的机制尽可能明确化、可检查化和可复算化，让人们更早看见：什么条件使某种关系变好，谁真正受益，谁承担代价，哪些边界不能被普通收益抵销，哪里仍然未知，以及一个看似更好的方案会在什么条件下失效。**

如果这些问题能够被更清楚地表达和共同检验，人们就更有可能在现实利己动机仍然存在的条件下，找到比无边界对抗、单方压制或成本转嫁更好的实现路径。

## 共同目标

参与这个项目，不要求先接受一套完整理论。无论是研究者、开发者、领域专家、机构还是独立团队，都可以围绕以下共同目标工作：

1. **把机制说清楚。** 把主体、利益、能力、资源、时间、约束、第三方影响和未知条件从模糊叙事中拆出来。
2. **把结果看完整。** 不只问“总体是否更好”，还要看谁改善、谁受损、谁被遗漏，以及哪些硬边界被跨越。
3. **把方案拿来比较。** 在同一组明确条件下比较不同互动规则，而不是只展示一个理想结果。
4. **主动寻找失败条件。** 找反例、边界、不可达条件和隐藏成本，而不是只积累支持性案例。
5. **让判断能够复算和质疑。** 尽可能让别人仅凭公开输入、规则和代码就能重复检查结果。
6. **让更好的机制能够被继续开发。** 把方法、示例和代码开放出来，让不同团队可以独立改进、替代、分叉或应用到自己的领域。
7. **不把研究工具变成现实权力。** 软件结果不自动成为公平认证、政策决定、法律结论、现实授权或对人的评分。

因此，参与者最重要的贡献不一定是“证明项目正确”。**证明某个机制不成立、指出一个无法表达的重要现实、提出更好的形式化方法，或者独立做出更好的实现，同样属于项目目标的实现。**

## 核心研究问题

当不同主体拥有不同利益、能力、信息、时间条件、依赖关系与退出选项时，改变互动规则之后究竟发生什么？谁改善、谁承担代价、哪些硬边界被跨越、哪些事实仍未知，以及所谓“改进”会在什么条件下失效？

## 当前软件目标

当前软件只是上述长期研究的一块最小“砖”。它不试图一次解决整个问题，而是先把其中一部分变成机器可检查对象：

- 表达主体、现实基线、候选安排、结果、资源与显式约束；
- 只比较可比的主体／维度／单位，不生成普遍“公平总分”；
- 把普通收益与硬约束、第三方保护分开；
- 明确保留 `UNKNOWN`，不把缺失事实静默补零或乐观推定；
- 区分输入非法与信息合法但未知；
- 输出确定、可检查、可独立复算的结果；
- 为后续新增场景和机制模块保留最小扩展路径。

## 方法

当前软件遵守五条方法纪律。

1. **先声明，再计算。** 程序只处理输入中明确给定的主体、数值、单位、资源和约束，不自行推断隐藏动机、真实偏好、法律权利或社会事实。
2. **维度分开。** 只有主体、维度和单位一致时才进行结果比较；不生成普遍公平、福利、合作或文明等级分数。
3. **硬约束不能被平均值吞掉。** 普通收益不能自动抵销已经违反的硬约束或第三方保护边界。
4. **未知是合法结果。** 合法输入中的关键值明确未知时输出 `UNKNOWN`；非法引用、未声明单位等则直接拒绝，不能伪装成未知。
5. **复算是结果的一部分。** 同一合法输入与同一软件版本应得到一致核心结果，并通过输入哈希支持复算定位。

## 应用方式

当前参考实现适用于：

- 教学与演示；
- 纯合成机制实验；
- 可复现研究原型；
- 多方独立二次开发；
- 显式规则集之间的比较；
- 由领域团队自行承担验证和治理责任的专业工具开发。

典型路径为：

`描述场景 → 声明基线与候选安排 → 声明约束 → 运行评估器 → 查看 SATISFIED / VIOLATED / UNKNOWN → 修改条件 → 重新计算`

## 范围

### 当前软件已经覆盖

当前版本支持本地 Python/JSON 工作流、合成场景、确定性比较、硬约束检查、明确未知、机器可读 JSON 输出、人类可读 Markdown 报告和自动测试。

### 长期研究方向，不是当前软件已经证明的能力

更大的研究计划未来可以继续研究谈判、供应链、劳动关系、平台治理、公共项目、联盟、阵营、共同体、公共品、能力发展、外部性、纠错与退出等多主体机制。

这些领域不共享一个万能制度。一个合成示例成功运行，不能证明现实机制有效，更不能自动外推至其他领域。

### 当前明确不做

本仓库不提供：

- 公平认证；
- 法律、政策、投资、就业、谈判或公共权力决策；
- 行为或动机预测；
- 人格、忠诚、合作度、意识形态或信誉评分；
- 自动最优政策搜索；
- 统一全球谈判或治理制度；
- 现实授权、执行、仲裁或代表权；
- 对输入事实真实、完整、正当或伦理可接受的保证。

正式研究母稿、受控盲测夹具、受限研究资料、个人数据以及其他未进入本仓库的资产，不因本仓库开源而自动纳入许可范围。

## 全球参与方式

项目设计目标是“可分叉、可接续”，而不是要求所有后续开发都依赖中心维护者。贡献者不需要先接受全部理论命题，才可以测试、批评或扩展软件。

有价值的贡献包括：

- 反例与失败场景；
- 更严格的输入校验；
- 更清晰的数据结构和文档；
- 复算与可重复性改进；
- 新的原创合成示例；
- 替代机制模块；
- 清楚限定适用范围的领域实现；
- 翻译与可访问性改进。

主仓库维护者可以决定是否合并贡献，但在 Apache-2.0 允许的范围内，下游独立开发不需要获得主仓库逐项审批。
