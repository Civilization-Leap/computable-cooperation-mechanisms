# Milestone A — Real-World Pilot Protocol

## Purpose

Milestone A is the first evidence gate for moving CCM from **publicly runnable infrastructure** to **documented domain use**.

The goal is intentionally narrow:

> Help one independent user materially improve one real, non-sensitive, reversible competition/cooperation decision, negotiation, arrangement, or rule choice — and leave enough evidence to show what changed.

This is **not** a request for endorsement, and it does not require the user to adopt CCM's broader theory.

## Suitable pilot problems

Prefer problems that are:

- real and current;
- non-sensitive or safely anonymizable;
- reversible or low-regret;
- multi-actor;
- involve at least two realistic alternatives;
- contain tradeoffs, third-party burdens, hard boundaries, or important unknowns;
- small enough to document within days or weeks rather than months.

Examples:

- supplier / buyer terms;
- open-source maintenance burden sharing;
- community or platform rule changes;
- team resource allocation;
- partnership scope, exit, or responsibility allocation;
- nonprofit / research collaboration terms;
- procurement or service-option comparison.

Do not use Milestone A for nuclear, weapons, biosecurity, life-critical, or other high-consequence irreversible decisions.

## Minimum evidence package

A pilot counts only if it records:

1. the user's own purpose;
2. the current baseline;
3. at least two real alternatives;
4. affected actors and third parties;
5. hard boundaries and UNKNOWNs;
6. what the current tool can and cannot represent;
7. what became visible that was not visible before;
8. whether the comparison changed a judgment, negotiation, arrangement, or next action;
9. a short confirmation from the user or decision participant;
10. the evidence level and any limitations.

## Evidence boundary

Milestone A can support a claim no stronger than:

> "A real external user used CCM in one documented, reversible domain case and reported a material improvement in problem visibility or decision quality."

It does **not** establish capability retention, repeated use, cross-actor diffusion, institutional change, or civilization accumulation. Those belong to later H-layer evidence.

## Direction and misuse gates

Before a pilot is published as a successful case:

- all seven direction-gate items are treated as critical;
- PASS / UNKNOWN / VETO must be recorded;
- UNKNOWN cannot be averaged away;
- any known third-party burden must remain visible in the report;
- declared vulnerability boundaries must not be converted into optimization targets against weaker actors;
- a VETO blocks promotion of the case as a reusable success template.

## Suggested workflow

**Bring a real problem → complete the Problem Card → map what fits → run or compare candidates → record representation gaps → review the result with the user → record what changed → classify A-I feedback → publish only the evidence actually supported.**

## What the maintainer provides

For the first pilot, the maintainer can help with:

- structuring the problem;
- anonymizing non-essential details;
- mapping the problem into current CCM fields;
- identifying what must remain UNKNOWN;
- running the current reference implementation where appropriate;
- producing a compact evidence card;
- recording representation gaps without forcing the problem into the tool.

## What the external participant provides

The participant should provide only what they are comfortable sharing:

- a real reversible problem;
- the decision purpose;
- two or more realistic alternatives;
- known constraints and affected actors;
- confirmation of whether the process changed what they saw or did.

No confidential, personal, regulated, or security-sensitive data is required.

## Success / non-success

### Milestone A PASS

A documented external user confirms that CCM materially improved problem visibility, comparison, or decision quality in a real reversible case, with the evidence package above.

### Milestone A PARTIAL

A real problem enters the process but the tool cannot represent it without distortion. This still counts as valuable A-F feedback, but not as demonstrated domain use.

### Milestone A FAIL / STOP

The case cannot be safely documented, becomes high-consequence, requires unsupported inference, or hits a direction-gate VETO.

## Next step after PASS

Do not immediately claim wider impact. Move to Milestone B only after an appropriate time window and ask whether the participant can reuse the method without maintainer help, or whether another independent actor reuses the same solution structure.
