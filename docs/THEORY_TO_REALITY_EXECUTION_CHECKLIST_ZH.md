# 从理论到现实｜执行检查表 V1.0

本表把《从理论到现实：思想、工具、应用与开放迭代的方法论》转化为可复用执行门。适用于新的思想理论、制度构想、治理框架或公共工具项目。

## A. 理论门
- [ ] 能用普通语言说明现实问题是什么。
- [ ] 能说明相较既有理解新增看见了什么。
- [ ] 能说明希望现实中的判断或行动发生什么变化。
- [ ] 已区分理论主张、事实主张与价值判断。

## B. 主体目的门
- [ ] 明确谁是使用主体。
- [ ] 允许主体声明自己的目的，而不是由工具替其规定目标。
- [ ] 已识别其他参与者和未在场承重者。
- [ ] 已说明主体目标与研究目标不同。

## C. 使用方法门
- [ ] 有一条非技术人员也能理解的最短使用路径。
- [ ] 能比较维持现状、行动、不行动及中间方案。
- [ ] 有硬边界、UNKNOWN、不可公开信息的位置。
- [ ] 明确什么结果会改变原判断。

## D. 工具门
- [ ] 只把适合计算的部分工具化。
- [ ] 输入、输出、版本和失败条件明确。
- [ ] 不把计算结果表述为事实、正当性、公平性或现实授权。
- [ ] 工具能拒绝不支持的输入，而不是静默补造。

## E. 真实使用门
- [ ] 至少有一个公开、非敏感、可复核的现实问题走完整流程。
- [ ] 允许“当前无法无失真表达”成为有效结果。
- [ ] 记录遗漏主体、遗漏约束、反例和误读风险。

## F. 迭代门
按最小充分层级升级：

`documentation → teaching example → reusable template → domain extension → core/schema`

- [ ] 单一案例不直接推动 core 扩张。
- [ ] 重复真实问题才形成模板候选。
- [ ] 重复领域结构且模板不足，才形成 domain extension。
- [ ] 只有跨领域、影响核心语义且可检验的结构，才进入 core/schema。

## G. 传播门
- [ ] 有思想入口：为什么值得关心。
- [ ] 有现实入口：与使用者什么问题有关。
- [ ] 有使用入口：怎样带自己的问题进入。
- [ ] 有技术入口：怎样运行和复算。
- [ ] 有验证入口：怎样反驳、复现或独立实现。

## H. 证据门
不得混淆：

`DRAFT → INTERNAL TEST → PUBLIC TEST → INDEPENDENT EXECUTION → INDEPENDENT REIMPLEMENTATION → DOMAIN USE → EXTERNAL VALIDATION`

- [ ] 内部自测不写成独立验证。
- [ ] AI 辅助核查不写成外部第三方证据。
- [ ] 下载、阅读、使用、采用、验证分别记录。

## I. 高后果门
- [ ] 早期优先用高冲突但可逆问题验证工具。
- [ ] 高后果问题优先用于检验边界，而非证明工具万能。
- [ ] 当模型不足时明确停止计算。

## J. 目的达成门
最终不以文稿数量、功能数量或曝光量作为成功判据，而检查：

- [ ] 是否有人因此看见以前没有看见的结构。
- [ ] 是否有人因此改变判断或提出更好的候选方案。
- [ ] 是否减少了本可避免的损失、误判或不可逆风险。
- [ ] 是否出现真实复用、质疑、扩展或独立实现。

> 最终检验：现实有没有因此变得更好一点。
