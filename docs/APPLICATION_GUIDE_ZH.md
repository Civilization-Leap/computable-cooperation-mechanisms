# 如何把竞争—合作可计算机制用于真实问题

## 目的：不是“使用一个工具”，而是帮助主体更清楚地实现自己的目标

本项目同时提供三样东西：

1. **理论**：为什么要同时比较合作与不合作、竞争与协调的收益、损害、风险与长期后果；
2. **工具**：把主体、结果、约束、第三方影响、未知项和失败条件显式化，并对已声明条件进行可复算检查；
3. **使用方法**：帮助不同主体把自己的目标、约束和候选方案带入比较过程，而不是让工具替主体决定目标。

真正的现实价值，不是软件给出一个“正确答案”，而是让原本隐藏在立场、谈判、组织惯性或冲突升级中的条件更早变得可见，使主体更有机会找到更好的竞争、合作或退出方式。

---

## 一、先从你的目的出发

不同主体进入这个项目时，不需要接受同一个目标。

企业可以关心利润、现金流、供应安全、增长、控制权与长期竞争力；员工可以关心收入、安全、尊严、职业发展和退出权；平台可以关心效率、增长、生态稳定和合规；政府和公共机构可以关心公共利益、风险、稳定、创新与长期韧性；研究者可以关心机制是否可证伪、可复算和可扩展；国际关系主体可以关心安全、威慑、误判、升级和不可逆后果。

**主体目标属于主体。项目不替主体设定目标。**

项目所做的是帮助主体追问：

- 我真正想实现什么？
- 哪些条件是必要约束？
- 哪些代价是我自己承担，哪些会转移给别人？
- 合作会得到什么、失去什么？
- 不合作会得到什么、失去什么？
- 竞争继续升级会发生什么？
- 降低竞争又可能失去什么？
- 有没有第三种安排？
- 哪些事实已知，哪些只是推断，哪些仍然未知？
- 哪些后果一旦发生就很难回头？

## 二、最小使用流程：从一个真实问题开始

### 第一步｜定义问题，而不是先定义答案

写清楚：

- 场景是什么；
- 有哪些直接主体；
- 哪些第三方可能被影响；
- 当前发生了什么；
- 你希望改变什么。

不要先写“合作一定更好”或“必须竞争到底”。

### 第二步｜分别写出各主体真正关心的东西

将“立场”和“利益/约束”分开。

例如：

- 立场：我不能降价；
- 可能的真实约束：现金流、最低毛利、产能风险、融资条件。

如果真实条件不能公开，可以只声明边界、范围或由可信第三方核验，不要求裸露全部底牌。

### 第三步｜同时建立至少两个候选方案

至少比较：

- **方案 A：合作 / 更深合作 / 当前提议**；
- **方案 B：不合作 / 保持现状 / 独立发展**。

必要时加入：

- 方案 C：有限合作；
- 方案 D：延迟决策；
- 方案 E：第三方担保、阶段性试验、退出条款、风险共担等新组合。

### 第四步｜把结果、约束和第三方影响显式化

对每个方案至少记录：

- 每个主体得到什么；
- 每个主体损失什么；
- 第三方承担什么；
- 哪些硬约束必须满足；
- 哪些结果无法确定；
- 哪些结果不可逆或恢复成本极高。

### 第五步｜用工具做机械核验

当前 v0.1.1 参考实现可以：

- 比较 baseline 与 candidate 的已声明变化；
- 对匹配的 actor + dimension + unit 计算 delta；
- 独立检查声明的硬约束；
- 保留 UNKNOWN，而不是自动填成 0；
- 明确拒绝未支持字段和不一致输入；
- 生成可复算结果与 hash。

它**不能**：

- 判断目标是否正当；
- 决定阈值应该是多少；
- 证明数据真实；
- 给主体贴道德标签；
- 推断动机；
- 预测现实行为；
- 替代真实谈判、法律授权或公共决策。

### 第六步｜回到人的判断和现实谈判

工具输出不是终点，而是下一轮讨论的输入。

需要追问：

- 为什么这条约束被设为这个值？
- 谁参与设定？
- 谁没有参与，却承担后果？
- 如果参数稍微变化，结论是否翻转？
- 哪个未知项最值得优先核验？
- 是否可以先做小规模、可退出、可回滚试验？

## 三、不同主体如何使用

### 1. 企业与商业谈判

**可能目的**：降低成本、稳定供应、提高利润、并购整合、减少违约风险、扩大市场。

**使用方式**：

1. 把价格、控制权、交付时间、现金流、风险承担、退出权拆成不同维度；
2. 比较合作与不合作的短期和长期后果；
3. 检查收益是否通过员工、供应商、客户或市场竞争度向第三方转移成本；
4. 对候选交易设计多种结构，而非只在一个价格上讨价还价；
5. 用小规模或阶段性安排验证承诺，再决定是否扩大合作。

**例：企业并购**

不要只比较“买 / 不买”。还可以比较：长期采购、少数股权、联合投资、供应担保、第二供应源、阶段性收购、附退出条件的合作。计算工具用于显示每种安排中已声明结果与约束的变化，不替董事会、股东、员工或监管者决定并购是否正当。

### 2. 员工、组织与劳动关系

**可能目的**：收入、安全、尊严、工作稳定、组织效率、持续经营。

**使用方式**：

- 把“涨薪 / 不涨薪”“裁员 / 不裁员”背后的真实约束拆开；
- 比较短期成本与长期流失、技能损失、信任损耗；
- 将弱势方不可承受的底线单独表示，而不是被整体收益抵销；
- 设计阶段性、可重谈、可退出的安排。

### 3. 平台与生态参与者

**可能目的**：增长、效率、用户体验、创作者/商户稳定、平台安全。

**使用方式**：

- 将平台收益、参与者收益、规则成本和第三方影响分开；
- 比较规则改变与不改变各自的后果；
- 检查同一规则是否让一方获得效率、另一方承担不可见风险；
- 保留申诉、纠错和重新谈判路径。

### 4. 公共治理与社会创新

**可能目的**：公共服务、效率、公平风险控制、社会稳定、创新。

**使用方式**：

- 明确谁受益、谁承担、谁缺席；
- 将不可被整体收益抵销的保护条件显式化；
- 对不同政策方案做透明的反事实比较；
- 把争议集中到“事实、阈值、权利与后果”上，而不是隐藏在总分里。

工具只能帮助显影和比较，不能自动赋予政策正当性。

### 5. AI / AGI 与高后果技术治理

**可能目的**：能力收益、安全、竞争优势、公共利益、降低不可逆风险。

**使用方式**：

- 同时比较部署与不部署、开放与限制、竞争升级与协调限制；
- 分开表示直接收益、系统风险、第三方承重和不可逆后果；
- 对“谁有权设安全阈值”保持显式，而不是把阈值隐藏成算法事实；
- 优先设计小规模、可退出、可回滚的试验路径。

**例：AI 军事化中的断链自主武器**

主体可能包括军方、国家、对手、平民、盟友、技术供应商和未来扩散环境。需要同时比较：使用带来的战术收益与人员风险下降；不使用可能带来的劣势；对方跟进后的军备升级；误识别与责任链断裂；技术扩散后对未来冲突门槛的影响。工具可以帮助把这些变量、约束和未知项显式化，但不能决定战争正当性，也不能授权武器使用。

### 6. 国际关系、联盟与冲突预防

**可能目的**：安全、威慑、主权、发展空间、危机稳定。

**使用方式**：

- 将“退让 / 不退让”背后的安全恐惧和承诺结构显式化；
- 同时计算合作与不合作的收益和损害；
- 对军备、安全困境和升级链做反事实比较；
- 找出哪些步骤会关闭未来谈判窗口；
- 在不存在兼容解时，至少把对抗代价和不可逆后果提前显影。

## 四、适合带入项目的问题

如果你有一个真实问题，可以按下面格式提交：

### BYOP｜Bring Your Own Problem

**1. 场景**  
发生了什么？

**2. 主体**  
谁直接参与？谁可能受影响？

**3. 各主体目标**  
他们分别希望实现什么？

**4. 当前立场**  
各方现在在说什么？

**5. 真实约束**  
哪些利益、底线、能力、风险真正决定行为？

**6. 候选方案**  
至少写出合作与不合作两个方案；如果有第三路径，也一起列出。

**7. 结果维度**  
钱、时间、安全、控制权、风险、机会、退出权、第三方影响等。

**8. 硬约束**  
哪些结果不可接受，不能被其他收益抵销？

**9. 未知项**  
哪些事实目前不知道？

**10. 不可逆项**  
哪些后果一旦发生，很难恢复？

**11. 希望工具帮助回答的问题**  
例如：哪种方案违反已声明底线？哪项未知最关键？某个阈值变化是否会使结论翻转？

## 五、怎样理解“达到目的”

本项目不承诺替任何主体“优化到最大收益”。

更准确地说，它希望帮助主体：

- 更清楚地定义自己的目的；
- 看见实现目的所需的真实条件；
- 看见自己的方案会给别人带来什么；
- 看见不合作的代价，而不是只看合作收益；
- 发现原本未被看见的第三路径；
- 在高后果决定前保留更多纠错空间；
- 用可核验履约逐步降低下一轮合作成本；
- 在无法合作时，也更清楚地理解对抗边界和代价。

因此，**理论负责解释为什么要这样看问题；工具负责让部分条件可以运行和复算；主体自己负责目标、价值判断、谈判、授权与现实行动。**
