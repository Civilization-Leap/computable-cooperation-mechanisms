# Bring Your Own Problem｜现实问题卡 V0.1

Use this card before writing JSON. It is intentionally short. The purpose is to turn a real competition/cooperation problem into an inspectable question without pretending that every part is computable.

## A. Your purpose

**1. Who are you in this situation?**  
Role only; do not disclose private identity unless necessary.

**2. What are you trying to achieve or protect?**  
State the purpose in your own terms. The project does not replace it with a project-defined goal.

**3. What would count as an unacceptable outcome for you?**

## B. Actors and effects

**4. Who else can materially affect the outcome?**

**5. Who may bear costs or risks without being at the negotiating table?**  
Include employees, customers, suppliers, communities, future users, or other affected parties when relevant.

## C. Compare choices, not slogans

For every candidate arrangement, including continued non-cooperation or the status quo where relevant, answer:

| Candidate | What may be gained? | What may be lost or damaged? | Who gains? | Who bears? | What remains unknown? |
|---|---|---|---|---|---|
| Baseline / status quo | | | | | |
| Candidate A | | | | | |
| Candidate B | | | | | |
| Candidate C (optional) | | | | | |

Do not label a candidate “cooperation” and assume that this makes it better. Do not label a candidate “competition” and assume that this makes it worse.

## D. Hard boundaries

**6. Which conditions must not be offset by ordinary gains?**  
Examples may include a safety limit, capacity limit, legal prohibition, minimum continuity condition, or a deliberately declared third-party protection.

For every hard boundary record:

- the rule;
- the unit;
- the threshold, if any;
- who proposed or authorized it;
- evidence/provenance if available;
- who is affected by it;
- how it can be challenged, changed, or appealed.

A computable threshold is not self-legitimating.

## E. Evidence and disclosure

**7. Which inputs are:**

- known and evidenced;
- declared but not independently verified;
- unknown;
- sensitive / not safe to disclose?

Do not turn an unknown into zero. Do not disclose a bargaining floor, personal data, security-sensitive fact, or trade secret merely to make the case computable.

## F. Falsifiability

**8. What result or evidence would make you change your current view?**

If the answer is “nothing,” the tool is likely being used to defend a conclusion rather than test an arrangement.

## G. What to return to the project

After attempting to model and run the case, return one or more of:

- a successful synthetic/anonymized case;
- a representation gap;
- a counterexample;
- a missing actor or impact;
- a missing hard constraint;
- an interpretation/misuse risk;
- a domain-extension proposal;
- a core defect.

Never submit confidential material to a public issue. Reduce, anonymize, or synthesize the case first.
